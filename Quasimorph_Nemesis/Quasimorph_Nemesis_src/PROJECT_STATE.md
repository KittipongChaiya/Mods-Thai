## Decisions

- 2026-09-02 — **A nemesis is a template, not a buffed creature.** Each rank produces a
  `MobClassRecord` cloned fresh from the untouched base class; the game builds an ordinary
  monster from it. This makes rank scaling idempotent by construction and is the single
  most important decision in the mod — see Retinue's `AllyPower` for the trap it avoids.
  `ConfigRecordCollection<T>.AddRecord` / `RemoveRecord` are public, which is what makes
  it possible.
- 2026-09-02 — **Shallow clone, scalar writes only.** `MobClassRecord` holds lists that the
  clone shares by reference with the base record. Mutating one would edit the class every
  ordinary enemy of that type is built from. Only value-typed fields are assigned.
- 2026-09-02 — **Naming rides the game's own path.** Names come from
  `monster.<mobClassId>.name` (confirmed against the Thai mod's `095_monster.json`).
  Because a nemesis has its own mob class, it asks for a key nothing defines, and a
  narrow `Localization.Get` postfix answers. No per-creature name plumbing, and the name
  is right in every UI at once. The postfix returns immediately for any key not starting
  `monster.nemesis_`, which matters because `Localization.Get` is the most contested
  method in a typical load order.
- 2026-09-02 — **Roster in the save, not in a file.** `ModHookType` has no save-writing
  hook, so this required patching `SerializeGlobalComponents`. A file beside the DLL would
  need no patch but would be wrong the moment the player loads an earlier save — normal
  play in this game, not an edge case.
- 2026-09-02 — **Promotion does not modify the enemy it reads.** It copies a mob class and
  faction into a row; the nemesis arrives later. A promotion can therefore never make the
  current floor harder than the player signed up for.
- 2026-09-02 — **Rank comes only from the player's own mercenary dying**, attributed via
  the public `DamageHitInfo.damageDealer` field held across to `OnPlayerDied`. Ally deaths
  do not feed a nemesis.
- 2026-09-02 — **Gear inheritance deferred to v0.2.** A returning nemesis is better armed
  through `EquipmentTechLevelBonus` and `Unit.TechLevelLimit`, which needs no item
  serialisation at all. Carrying the player's specific dropped items across raids needs
  condition and ammo state persisted and is the heaviest, least reliable part of the idea.

## Next Action

Launch with the mod installed and check, in order:

1. `QuasimorphNemesis.log` says *"all 6 patches attached"*. If the two
   `GlobalComponents` patches failed, stop — the roster cannot persist and nothing else
   is worth testing.
2. Set `promote_chance=1.0` and enter a raid; the log should name a promotion.
3. Enter another raid; the named nemesis should arrive and be **named on screen** — this
   is the one inference in the design (that the injected mob class drives the displayed
   name) and the thing most likely to be wrong.
4. Let it kill your mercenary; confirm the log ranks it up.
5. Save, reload, confirm the roster survives with the same names and ranks.
6. Kill it; confirm it retires and never returns.
7. **Confirm ordinary enemies of the same base class are unchanged** — the check that
   matters most.
